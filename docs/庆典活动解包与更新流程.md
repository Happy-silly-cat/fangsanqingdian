### 获取最新资源

先让用户在游戏内完成更新并打开本期庆典，等资源下载完成。只读取活动所需文件，不导出账号、支付 SDK、登录缓存或日志中的敏感信息。

离线读取虚拟磁盘只允许使用关闭模拟器后的副本或一致性快照，并需另行确认可用读取工具。不要改动运行中的 `data.vdi`、`data.raw`；本流程没有已验证的离线磁盘提取脚本。

## 二、先确认最新活动时间

本次 `ActivityConfig.cfg.game40010254` 是 UTF-8 文本形式的 Lua 风格数据表，不需要先做 FEFE 解码。

查找入口时可先搜索：

```powershell
rg -n '"anniv"|"annivTask"|"start_time"|"end_time"' $configPath
```

搜索仅用于定位。正式提取使用数据解析器，或尊重字符串、转义和嵌套括号的结构扫描器；不要用“截取到下一个活动名”的字符串方式解析。不执行不可信 Lua 脚本。

本期配置的关系是：

- `anniv`：活动入口，给出 `start_time`、`end_time`、`version` 和本期启用的兑换、任务、宝箱 ID。
- `annivTask`：这些 ID 的具体定义，包括兑换奖励、兑换消耗、次数及任务信息。
- `need_open_time` 不是活动开始时间；`version` 不是活动结束时间。
- `anniver`、`anniver2`、`annivTwelve`、`festivalActive` 等名称不一定指同一个活动。以后活动入口或键名改变，要重新定位，不能固定只认 `anniv`。

Unix 秒级时间戳用明确时区换算，勿依赖执行机器的默认时区：

```powershell
$zone = [TimeZoneInfo]::FindSystemTimeZoneById('China Standard Time')
$start = [DateTimeOffset]::FromUnixTimeSeconds([long]$startTime)
$end = [DateTimeOffset]::FromUnixTimeSeconds([long]$endTime)
[TimeZoneInfo]::ConvertTime($start, $zone).ToString('yyyy-MM-dd HH:mm:ss')
[TimeZoneInfo]::ConvertTime($end, $zone).ToString('yyyy-MM-dd HH:mm:ss')
```

2026-10-03 已有快照的核对基准：`anniv.start_time=1790784000`，`end_time=1791388799`，对应北京时间 **2026-10-01 00:00:00 至 2026-10-07 23:59:59**。这只是本期记录，下次必须重读。

遇到多个入口、不同时间或旧新配置冲突时，记录候选并以当前游戏界面和适用条件复核。尚未开始、已结束、预载下一期都不能直接标成“当前进行中”。

## 三、提取本期兑换道具

从 `anniv.data` 对应活动记录的 `exchange` 字段读取启用 ID，再到 `annivTask.data` 找对应记录。本期为 `100001` 至 `100010`，不要把 `annivTask` 中所有行都当作本期兑换。

逐条保留：

| 字段 | 提取内容 |
| --- | --- |
| `id` | 兑换条目 ID |
| `exchange_get` | 每次兑换奖励，保留原始类型、物品 ID、数量 |
| `exchange_cost` | 每次兑换消耗，逐项保留物品 ID 和数量 |
| `exchange_times` | 本期限兑次数，勿与任务购买限制混淆 |
| 物品表信息 | 最新名称、描述、图标引用、礼包类型 |
| 礼包内容 | 每个可选项的类型、ID、数量和图标 |

常见奖励串为 `type|id|quantity`，多项用逗号分隔。类型含义需对照当期数据和客户端；不能把所有 ID 都当普通道具。数量和限兑是两个概念：“神兵洗炼石 ×5”表示每次兑换得到 5 个，不是消耗材料乘 5，也不是限兑 5 次。

物品数据库先读取 `keys`，按字段名对应每条记录的位置。不要固定列号，Lua 的字符串、逗号、转义和 `nil` 都必须正确处理。

名称和图标查找顺序：兑换条目物品 ID → 对应 `DB_Item_*` 表 → 名称与 `icon_small` / `icon_big` 等字段。礼包再检查 `choose_items` 和 `DB_Item_direct.lua` 等关联表，递归解析引用。“可选内容”不得展示成“一次全都获得”。

本期 ID 仅供查找参考：红灯笼 `60632`；节、日、快、乐 `60694`、`60695`、`60696`、`60697`；助庆材料包 `20164`；礼包 `20820`、`20822`、`20614`、`20817`。旧活动名称可能变化，以最新表为准。

## 四、解包物品表与图片

已将现有解码脚本另存为稳定路径，不再依赖临时目录：

| 脚本 | 用途与边界 |
| --- | --- |
| `docs/celebration-tools/decode-db.cjs` | FEFE 包装的标准自动生成 Lua 物品表；从脚本所在目录的 `db` 读取，输出至 `decoded` |
| `docs/celebration-tools/decode-hot-update-png.cjs` | 部分 FEFE PNG 的 16 周期解码；直接改写参数指定的图片副本 |
| `docs/celebration-tools/decode-png-extended.cjs` | 部分 17 至 22 周期 PNG 的备用解码；搜索较慢，成功前检查块 CRC 与 IEND |

这是已存档工具，不是任意新格式都通用的解包器。使用前确认 Node.js 的真实路径；本机未必配置了 `node` 命令。

本次 Codex 内置 Node 路径如下；以后可通过工作区依赖工具重新定位：

```powershell
$node = 'C:\Users\55471\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe'
$project = 'C:\Users\55471\Desktop\fangsanqingdian'
```

### 物品表解码

确认 `working\db` 只放本次需要解析的原始表副本，将脚本复制到 `working` 后运行：

```powershell
Copy-Item -LiteralPath (Join-Path $project 'docs\celebration-tools\decode-db.cjs') -Destination (Join-Path $work 'working\decode-db.cjs')
& $node (Join-Path $work 'working\decode-db.cjs')
```

其已知格式：文件头 `FE FE FE FE`，跳过 32 字节包装，从标准自动生成注释推导循环 XOR 密钥，仅处理正文偶数偏移字节。无包装文件会原样复制；不匹配标准注释的文件会跳过。

每次使用新输出目录，逐个检查需要的表是否解码成功、有 `keys` 和对应物品记录。日志的文件总数包含已有输出，不是本次成功数。该脚本不是通用 UI Lua 反编译器；`annivTwelve` 等脚本尚未确认可用这个方法解码。

特别注意：历史 `apk_current` 目录中有约 49 字节的 `.lua`，内容其实是 `/system/bin/sh: shell: inaccessible or not found`。文件存在、扩展名正确都不代表提取成功，必须检查内容与拉取退出码。

### 定位并解码真实图标

1. 从最新物品表取得图标文件名和类别路径，结合 `filedata.plist` 或资源目录定位实际文件。
2. 优先查找本期热更新图；缺少时再查当前 APK，记录来源。同名如 `2.png` 必须结合目录、类别和内容区分。
3. 原图复制到独立工作目录，再解码。已有标准 PNG 签名的图片直接检验，不再去掉 32 字节。
4. 若引用是图集帧，查找对应 plist 和整张 PNG，按帧坐标、旋转与裁剪信息还原；不能把整张图集当单个道具图。

```powershell
# 此变量必须指向工作副本，不能指向原始资源或已上线图片。
$pngCopy = Join-Path $work 'working\icons\denglong.png'
& $node (Join-Path $project 'docs\celebration-tools\decode-hot-update-png.cjs') $pngCopy
```

16 周期脚本只验证解码后的 PNG 签名，并不保证全部图片块正确。运行后必须独立检查尺寸、PNG 块 CRC、IEND 以及实际加载结果；能看到文件头但图片花屏仍算失败。

如普通解码失败或完整性检查未通过，**从原始资源重新复制一份**，再试备用脚本；不要在已改写的失败输出上继续解码：

```powershell
& $node (Join-Path $project 'docs\celebration-tools\decode-png-extended.cjs') $pngCopy
```

备用脚本对已解码的普通 PNG 会返回不支持，不能用于批量判断普通图片有效性。新加密格式、不同 PNG 布局或 Lua 字节码需另行分析；记录失败文件，不静默跳过或伪造图标。

## 五、更新并展示

先生成独立的当期清单和新旧差异，再修改页面数据，避免未核对数据直接替换已用版本。

- `assets/celebration-current-data.js`：更新活动起止、兑换项、消耗、限兑、礼包内容和真实图片引用。记录来源及资源获取时间。
- `assets/celebration-items/`：只放验证通过的图片。现有其他目录中对应物品的真实图片可复用，但要验证引用仍正确。
- `celebration.html`：按现有展示方式接入数据，必要时更新缓存版本引用；不顺带重做布局。

**三种时间分别记录**：游戏活动时间来自配置；资源获取时间来自实际获取记录；计算器更新时间来自页面修改时间。三者不可互换。旧数据中的 `sourceUpdatedAt: 2026-10-03 00:35` 不得沿用为下一期更新时间。

用户已确定的展示约束：保留目标选择和真实物品图标；限兑简写；完整兑换表、礼包卡片和旧购买表的结构已经注释，保留注释，不自动恢复。三个折叠入口保持统一外观、集中排列、默认收起。需要额外展示完整资源时，另做当期核对清单或预览，不改变主页面既有取舍。

活动更新会影响保存数据。当前 sessionStorage 的键含活动开始时间；新一期应隔离旧选择，同一期限兑变化时也需校验旧输入，不让用户保留超限数量。

### 计算部分只做必要核对

## 常见问题

| 现象 | 处理 |
| --- | --- |
| ADB 连着，但私有资源读不到 | 检查读取权限，使用授权最新导出；不重复把失败拉取当成功 |
| 新 APK 与游戏活动时间不一致 | 活动可能热更新；核对当前配置，APK 仅作辅助 |
| 配置没有 `anniv` | 重新定位本期入口，不强套旧键名 |
| 解码输出为空或只是报错文字 | 检查原始头部、长度、退出码和解码格式，保留失败记录 |
| 道具同 ID 名称改变 | 用本期表更新名称，同时保留 ID 与变化记录 |
| 只有图标名但没有独立图片 | 查资源清单及图集映射，不用无关图替代 |
| 页面图标正常但计算数据不符 | 区分展示更新与算法适配，核对模型中的固定参数 |

后续维护本流程时，补充新发现的入口、资源格式和已验证方法，保留适用版本与失败边界，不用一次成功推断所有未来活动都相同。
